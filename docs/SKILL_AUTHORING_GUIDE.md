# Agentic Browser: Skill Authoring Guide

Skills are reusable, versioned, portable automation programs executed by the Skill Engine. This guide provides the complete specification for authoring robust skills.

---

## 1. Canonical 16-Field Skill Specification

Every skill manifest (`.skill.json`) must strictly validate against `packages/shared/src/schemas/skill.schema.json` and contain the following 16 fields:

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `string` | Unique identifier (`[a-z0-9-]+`). Example: `github-star-repo`. |
| `name` | `string` | Human-readable title of the skill. |
| `description` | `string` | Clear summary of what the skill performs. |
| `version` | `string` | Semver version string (`X.Y.Z`). Example: `1.0.0`. |
| `schema_version` | `string` | Version of the skill specification standard (`1.0.0`). |
| `parameters` | `object` | Typed input parameters required by the skill. |
| `triggers` | `array<string>` | Natural language prompts or keywords that match this skill. |
| `domains_allowed` | `array<string>` | Whitelist of allowed web domains. |
| `steps` | `array<Step>` | Ordered array of executable actions. |
| `risk_level` | `string` | Risk classification: `low`, `medium`, `high`, `critical`. |
| `requires_confirmation`| `boolean` | Whether operator approval is required before execution. |
| `tests` | `array<object>` | Acceptance test cases validating the skill. |
| `success_metrics` | `object` | Post-execution verification criteria. |
| `provenance` | `string` | Author, repository, or origin of the skill. |
| `signature` | `string` | Cryptographic signature of the manifest content. |
| `changelog` | `array<object>` | Version history and migration notes. |

---

## 2. Step Object Specification

Each element in the `steps` array must define:

```json
{
  "id": "step-1",
  "action": "click",
  "target": {
    "selector": "button#checkout",
    "role": "button",
    "name": "Complete Checkout",
    "text": "Checkout"
  },
  "value": null,
  "expect": {
    "condition": "url_contains:/order-confirmation"
  },
  "on_fail": "repair"
}
```

- **`action`**: One of `navigate`, `click`, `fill`, `select`, `press_key`, `scroll`, `extract`, `wait`, `upload`, `download`, `finish`.
- **`target`**: Multi-strategy target object. Supplying `role`, `name`, and `text` enables the SelfRepairEngine to locate the element even if `selector` changes.
- **`expect`**: Verification condition to evaluate after step execution (e.g. `url_contains:...`, `value_equals:...`, `element_visible:...`).
- **`on_fail`**: Recovery directive: `retry`, `repair`, or `abort`.

## 3. Example Canonical Skill Manifest

```json
{
  "id": "search-knowledge-base",
  "name": "Search Knowledge Base",
  "description": "Searches documentation portal and extracts first result",
  "version": "1.0.0",
  "schema_version": "1.0.0",
  "parameters": {
    "query": { "type": "string", "description": "Search query" }
  },
  "triggers": [
    "search documentation for",
    "lookup doc",
    "find article"
  ],
  "domains_allowed": [
    "docs.example.org"
  ],
  "steps": [
    {
      "id": "nav-1",
      "action": "navigate",
      "target": { "url": "https://docs.example.org/search" },
      "value": null,
      "expect": { "condition": "element_visible:input[type=search]" },
      "on_fail": "abort"
    },
    {
      "id": "fill-search",
      "action": "fill",
      "target": {
        "selector": "input#query",
        "role": "searchbox",
        "name": "Search documentation"
      },
      "value": "{{query}}",
      "expect": {},
      "on_fail": "repair"
    },
    {
      "id": "submit-search",
      "action": "press_key",
      "target": { "selector": "input#query" },
      "value": "Enter",
      "expect": { "condition": "element_visible:.search-results" },
      "on_fail": "retry"
    }
  ],
  "risk_level": "low",
  "requires_confirmation": false,
  "tests": [
    {
      "name": "basic-search",
      "input": { "query": "installation" },
      "expected_outcome": "Results list visible"
    }
  ],
  "success_metrics": {
    "expected_min_results": 1
  },
  "provenance": "author:team@agenticbrowser.org",
  "signature": "ED25519_SIGNATURE_HEX",
  "changelog": [
    { "version": "1.0.0", "notes": "Initial release" }
  ]
}
```

## 4. Best Practices for Long-Term Maintenance

1. **Avoid Brittle CSS Selectors**: Never use dynamic autogenerated classes (e.g. `div.css-1a2b3c4`). Use semantic ARIA attributes or custom attributes (e.g. `[data-testid=submit-btn]`).
2. **Always Provide Multi-Strategy Targets**: Populate `role` and `name` so self-repair succeeds when class names change.
3. **Reference Vault Parameters**: Never hardcode credentials or secrets. Use parameter templates like `{{vault.account_password}}`.
4. **Scope Allowed Domains**: Only list the minimum required domain origins in `domains_allowed` to prevent unintended cross-domain navigation.
